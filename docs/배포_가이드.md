# 배포 가이드 (AWS EC2 한 대)

구성: EC2 한 대에 MySQL(Docker), Spring 서버, Nginx(프론트 정적 파일 + `/api` 프록시)를 함께 둔다.
프론트와 백엔드가 같은 주소라 CORS와 HTTPS 혼합 문제가 없다.

```
브라우저 → Nginx :80 ─┬─ /api, /swagger-ui → Spring :8080 → MySQL :3306(127.0.0.1)
                      └─ 그 밖 → /home/ubuntu/fe/dist (프론트 빌드 결과)
```

## 1. EC2 만들기 (처음 한 번)

1. AWS 콘솔 → EC2 → 인스턴스 시작
   - Ubuntu 24.04, t3.micro(프리티어) 또는 t3.small
   - 키 페어 새로 만들기 → `.pem` 저장 (GitHub Secret 에 넣음)
   - 보안 그룹 인바운드: SSH 22(내 IP), HTTP 80(0.0.0.0/0), HTTPS 443(0.0.0.0/0)
   - 스토리지 20GB
2. 탄력적 IP(Elastic IP) 할당 후 인스턴스에 연결 (재시작해도 주소 유지)

## 2. 서버 준비 (처음 한 번, SSH 접속 후)

```bash
# 스왑 2GB (1GB 메모리에서 Spring + MySQL 을 같이 돌리려면 필수)
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# Java 21, Nginx, Docker
sudo apt update && sudo apt install -y openjdk-21-jre-headless nginx docker.io docker-compose-v2 psmisc
sudo usermod -aG docker ubuntu   # 다시 접속해야 적용

sudo timedatectl set-timezone Asia/Seoul
mkdir -p /home/ubuntu/app /home/ubuntu/fe/dist
```

## 3. 비밀값 (`/home/ubuntu/app/.env`)

GitHub 에 올리지 않는다. 서버에서 직접 만든다.

```bash
cat > /home/ubuntu/app/.env << 'EOF'
DB_ROOT_PASSWORD=루트비밀번호
DB_USERNAME=dotorich
DB_PASSWORD=앱비밀번호
JWT_SECRET=32자이상_무작위_문자열
KAKAO_CLIENT_ID=카카오_REST_API_키
KAKAO_CLIENT_SECRET=
KAKAO_ADMIN_KEY=카카오_어드민_키
GEMINI_API_KEY=
CORS_ALLOWED_ORIGINS=http://탄력적IP,http://localhost:5173
EOF
chmod 600 /home/ubuntu/app/.env
```

## 4. MySQL, Nginx (처음 한 번)

레포의 `deploy/` 파일 두 개를 서버로 복사한다 (scp 또는 내용 붙여넣기).

```bash
cd /home/ubuntu/app
docker compose -f docker-compose.prod.yml --env-file .env up -d

sudo cp nginx.conf /etc/nginx/sites-available/dotorich
sudo ln -sf /etc/nginx/sites-available/dotorich /etc/nginx/sites-enabled/dotorich
sudo rm -f /etc/nginx/sites-enabled/default
sudo chmod o+x /home/ubuntu   # Nginx 가 fe/dist 를 읽을 수 있게
sudo nginx -t && sudo systemctl reload nginx
```

## 5. 백엔드 배포 (GitHub Actions)

1. BE 레포 Settings → Secrets and variables → Actions 에 추가
   - `EC2_HOST`: 탄력적 IP
   - `EC2_USERNAME`: `ubuntu`
   - `EC2_SSH_KEY`: `.pem` 파일 내용 전체
2. `main` 에 push 하면 `.github/workflows/deploy.yml` 이 jar 를 빌드해서 올리고 다시 실행한다. Actions 탭에서 수동 실행(Run workflow)도 된다.
3. 확인: `http://탄력적IP/api/v1/health`, `http://탄력적IP/swagger-ui.html`

서버가 켜질 때 자동으로 들어가는 데이터
- `data.sql`: 섹터, 단계, 캐릭터, 기본 용어 (INSERT IGNORE 라 재배포해도 안전)
- `resources/seed/*.json`: 문제, 용어 (민지님 시드 로더, 같은 id 는 덮어씀)

## 6. 프론트 배포

FE 레포에서 빌드해서 `dist` 를 서버로 올린다. 같은 주소라 API 주소는 비워 둔다.

```bash
# FE 레포 .env.production
VITE_API_BASE_URL=
VITE_KAKAO_REST_API_KEY=카카오_REST_API_키

npm run build
scp -i 키.pem -r dist/* ubuntu@탄력적IP:/home/ubuntu/fe/dist/
```

## 7. 카카오 디벨로퍼스

- 플랫폼 → Web 사이트 도메인: `http://탄력적IP`, `http://localhost:5173`
- 카카오 로그인 → Redirect URI: `http://탄력적IP/oauth/kakao`, `http://localhost:5173/oauth/kakao`

## 자주 보는 것

| 상황 | 명령 |
|---|---|
| 서버 로그 | `tail -f /home/ubuntu/app/app.log` |
| 서버 재시작 | Actions 에서 Run workflow |
| DB 접속 | `docker exec -it dotorich-mysql mysql -u dotorich -p dotorich` |
| 메모리 | `free -h` |

## 나중에 (필요해지면)

- HTTPS: 무료 도메인(duckdns 등) 연결 후 `sudo apt install certbot python3-certbot-nginx && sudo certbot --nginx`
- 프론트 자동 배포: FE 레포에 같은 방식의 Actions 추가
