# 배포 가이드 (AWS EC2 + Docker, 멋사 배포 세션 방식)

EC2 한 대에서 `deploy/docker-compose.yml`로 앱과 MySQL을 컨테이너로 띄우고, Nginx가 프론트 화면과 `/api`를 같은 주소(80)로 내보낸다.

```
브라우저 → Nginx :80 ─┬─ /api, /swagger-ui → 앱 컨테이너 :8080 (127.0.0.1) → MySQL 컨테이너
                      └─ 그 밖 → /home/ubuntu/fe/dist (프론트 빌드 결과)
```

## 1. EC2 만들기 (처음 한 번)

1. AWS 콘솔 → EC2 → 인스턴스 시작
   - 이름 `dotorich-server`, AMI **Ubuntu**, 유형 `t3.micro`
   - 키 페어 새로 만들기(`.pem`). **레포 폴더 안에 두지 않는다** (`.gitignore`가 막지만 습관적으로)
   - 네트워크 설정 → 편집 → 인바운드: SSH 22, HTTP 80, HTTPS 443 (8080은 열지 않는다)
   - 스토리지 **16GiB**
2. 탄력적 IP 할당 → 인스턴스에 연결 (껐다 켜도 주소 유지. 카카오 Redirect URI, 도메인 연결에 필요)

## 2. 접속 (Windows PowerShell)

```powershell
icacls.exe <pem-경로> /reset
icacls.exe <pem-경로> /grant:r "$($env:USERNAME):(R)"
icacls.exe <pem-경로> /inheritance:r
ssh -i <pem-경로> ubuntu@<탄력적-IP>
```

## 3. 서버 준비 (처음 한 번)

```bash
# Docker
sudo apt update && sudo apt install -y docker.io docker-compose-v2 nginx
sudo systemctl enable --now docker
sudo usermod -aG docker ubuntu
exit   # 다시 접속해야 docker 그룹이 적용됨

# 스왑 2GB (빌드 중 메모리 부족 방지, 필수)
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h   # Swap 2.0Gi 확인

sudo timedatectl set-timezone Asia/Seoul
```

## 4. 코드 받기와 비밀값

```bash
git clone -b main https://github.com/LikeLion-14th-La2on/BE.git dotorich-BE   # 공개 레포, 배포는 main 기준
cd dotorich-BE/deploy
cp .env.example .env
nano .env   # 값 채우기 (아래)
chmod 600 .env
```

| 키 | 값 |
|---|---|
| DB_ROOT_PASSWORD, DB_PASSWORD | 직접 정한 비밀번호 (예시 값 그대로 쓰지 않기) |
| JWT_SECRET | `openssl rand -base64 48` 결과 |
| KAKAO_CLIENT_ID / CLIENT_SECRET / ADMIN_KEY | 카카오 디벨로퍼스 앱 키 |
| GEMINI_API_KEY | AI 튜터 키 (비우면 가짜 튜터) |
| CORS_ALLOWED_ORIGINS | `http://<탄력적-IP>,http://localhost:5173` |

## 5. 실행

```bash
cd ~/dotorich-BE/deploy
docker compose up -d --build   # 처음엔 빌드 포함 몇 분
docker compose ps              # dotorich-app, dotorich-mysql 둘 다 Up
docker compose logs -f app     # "[시드] 용어 48/48개, 문제 63/63개 반영" 과 "Started" 확인 (Ctrl+C 로 빠져나옴)
curl http://localhost:8080/api/v1/health
```

서버가 켜질 때 자동으로 들어가는 데이터
- `data.sql`: 섹터, 단계, 캐릭터, 기본 용어 (INSERT IGNORE)
- `resources/seed/*.json`: 문제 63개, 용어 48개 (같은 id 는 덮어씀)

## 6. Nginx (처음 한 번)

```bash
sudo cp ~/dotorich-BE/deploy/nginx.conf /etc/nginx/sites-available/dotorich
sudo ln -sf /etc/nginx/sites-available/dotorich /etc/nginx/sites-enabled/dotorich
sudo rm -f /etc/nginx/sites-enabled/default
mkdir -p /home/ubuntu/fe/dist && sudo chmod o+x /home/ubuntu
sudo nginx -t && sudo systemctl reload nginx
```

확인: 브라우저에서 `http://<탄력적-IP>/api/v1/health`, `http://<탄력적-IP>/swagger-ui.html`

## 7. 다시 배포 (코드가 바뀔 때마다)

```bash
cd ~/dotorich-BE && git pull   # develop → main PR 머지 후
cd deploy
docker compose stop app          # 1GB 서버라 빌드 중 메모리를 아끼려고 앱을 먼저 멈춤
docker compose up -d --build
```

DB 데이터는 `db_data` 볼륨에 남아서 재배포해도 유지된다. **`docker compose down -v` 는 DB까지 지우니 쓰지 않는다.**

## 8. 프론트 배포

FE 레포에서 빌드한 `dist` 를 서버로 올린다. 같은 주소라 API 주소는 비워 둔다.

```bash
# FE 레포 .env.production
VITE_API_BASE_URL=
VITE_KAKAO_REST_API_KEY=<카카오 REST API 키>

npm run build
scp -i <pem-경로> -r dist/* ubuntu@<탄력적-IP>:/home/ubuntu/fe/dist/
```

## 9. 카카오 디벨로퍼스

- 플랫폼 → Web 사이트 도메인: `http://<탄력적-IP>`, `http://localhost:5173`
- 카카오 로그인 → Redirect URI: `http://<탄력적-IP>/oauth/kakao`, `http://localhost:5173/oauth/kakao`

## 10. HTTPS (도메인을 받으면)

HTTP 는 토큰이 평문으로 오가서 시연용으로만 쓴다. 서브도메인을 받으면:
1. DNS A 레코드를 탄력적 IP 로
2. `deploy/nginx.conf` 의 `server_name _;` 을 도메인으로 바꿔 다시 복사
3. `sudo apt install -y certbot python3-certbot-nginx && sudo certbot --nginx -d <도메인>`
4. 카카오 Redirect URI 와 `CORS_ALLOWED_ORIGINS` 를 `https://<도메인>` 으로 바꾸고 `docker compose up -d`

## 자주 쓰는 명령

| 상황 | 명령 (deploy 폴더에서) |
|---|---|
| 앱 로그 | `docker compose logs -f app` |
| 상태 | `docker compose ps` |
| DB 접속 | `docker exec -it dotorich-mysql mysql -u dotorich -p dotorich` |
| 디스크 부족 | `docker system prune -a -f` (볼륨은 안 지움) |
| 메모리 | `free -h` |
